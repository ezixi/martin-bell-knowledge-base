## Philosophy

The [`philosophy/`](./philosophy/) documents describe the principles I use when approaching data problems.

They are not intended as abstract theory. They have developed from the projects and organisational problems described elsewhere in this repository.

### Data Strategy

Start with the organisation, its decisions and its users before choosing architecture or technology.

### Analytics

Analytics exists to improve decisions and outcomes, not simply to produce dashboards and reports.

### Engineering Practices

Data systems should be treated as production software: versioned, reviewable, testable, observable and safe to change.

### Governance

Governance should create trust and enable safe self-service rather than create unnecessary bureaucracy.

### Leadership

Strong technical direction, high standards, team development, autonomy, culture and business alignment should reinforce one another.

### Semantic Layers

A semantic layer is the contract through which fragmented technical data becomes agreed business meaning that can be consumed consistently by humans and AI.

## Designed for Humans and AI

This repository is intentionally written to work well both as documentation and as input to AI systems.

Most documents contain structured YAML metadata describing areas such as:

* Role.
* Domain.

## Accuracy and Evidence

I have tried to distinguish clearly between:

* Work I personally delivered.
* Work I contributed to.
* Architecture I proposed.
* Projects that were started but not completed.
* Measured outcomes.
* Estimates.
* Lessons and opinions formed afterwards.

Where a project did not reach production or an outcome was not measured, I prefer to say so rather than imply otherwise.

Some older projects rely on notes and historical records rather than complete contemporary documentation. Approximate figures are described as such where relevant.

## Using This Repository With AI
